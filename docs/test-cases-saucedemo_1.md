# Тест-кейсы для веб-приложения (по аналогии с SauceDemo)

Предполагаемые модули приложения: авторизация, каталог товаров, страница товара, корзина, оформление заказа, меню/логаут.

---

## 1. Модуль авторизации (Login)

### TC-01. Успешный вход с валидными данными

**Предусловия:** пользователь на странице логина, есть валидные логин/пароль.
**Шаги:**

1. Ввести валидный username.
2. Ввести валидный password.
3. Нажать "Login".
   **Ожидаемый результат:** пользователь авторизован, происходит переход на страницу каталога товаров.

### TC-02. Вход с неверным паролем

**Шаги:**

1. Ввести валидный username.
2. Ввести неверный password.
3. Нажать "Login".
   **Ожидаемый результат:** отображается сообщение об ошибке, вход не выполнен, пользователь остаётся на странице логина.

### TC-03. Вход с несуществующим логином

**Шаги:** ввести несуществующий username и любой password, нажать "Login".
**Ожидаемый результат:** сообщение об ошибке о неверных учётных данных.

### TC-04. Вход с пустыми полями

**Шаги:** оставить поля username и password пустыми, нажать "Login".
**Ожидаемый результат:** сообщение о том, что username/password обязательны для заполнения.

### TC-05. Вход с пустым полем password (username заполнен)

**Шаги:** заполнить username, оставить password пустым, нажать "Login".
**Ожидаемый результат:** сообщение об ошибке о необходимости ввести пароль.

### TC-06. Вход заблокированным пользователем (locked_out_user)

**Шаги:** ввести данные пользователя, статус которого "заблокирован", нажать "Login".
**Ожидаемый результат:** отображается сообщение о блокировке аккаунта, вход невозможен.

### TC-07. Проверка чувствительности полей к регистру

**Шаги:** ввести валидный username в другом регистре (например, заглавными буквами).
**Ожидаемый результат:** система корректно обрабатывает ввод согласно ожидаемому поведению (либо вход выполнен, либо ошибка — зафиксировать фактическое поведение как эталон).

### TC-08. Проверка полей на XSS/спецсимволы

**Шаги:** ввести в поля username/password спецсимволы и скрипты (`<script>alert(1)</script>`).
**Ожидаемый результат:** ввод не выполняет скрипт, обрабатывается как обычный текст, вход отклонён с ошибкой.

## 2. Каталог товаров (Inventory)

### TC-09. Отображение списка товаров после логина

**Предусловия:** пользователь авторизован.
**Ожидаемый результат:** отображается список товаров с названием, изображением, ценой и кнопкой "Add to cart" для каждого.

### TC-10. Сортировка товаров по цене (по возрастанию/убыванию)

**Шаги:**

1. Открыть выпадающий список сортировки.
2. Выбрать "Price low to high".
   **Ожидаемый результат:** товары отсортированы по возрастанию цены.
   **Доп. проверка:** повторить с "Price high to low" — товары отсортированы по убыванию.

### TC-11. Сортировка товаров по названию (A-Z / Z-A)

**Шаги:** выбрать сортировку "Name A to Z", затем "Name Z to A".
**Ожидаемый результат:** список товаров пересортирован соответственно алфавиту.

### TC-12. Переход на страницу товара по клику на название/изображение

**Шаги:** кликнуть на название товара в каталоге.
**Ожидаемый результат:** открывается страница с подробным описанием этого товара.

### TC-13. Добавление товара в корзину из каталога

**Шаги:** нажать "Add to cart" у товара.
**Ожидаемый результат:** кнопка меняется на "Remove", иконка корзины показывает счётчик "1".

### TC-14. Удаление товара из корзины прямо из каталога

**Шаги:** для товара, уже добавленного в корзину, нажать "Remove".
**Ожидаемый результат:** кнопка снова "Add to cart", счётчик в иконке корзины уменьшается на 1 (или исчезает при 0).

### TC-15. Добавление нескольких товаров подряд

**Шаги:** добавить в корзину 3 разных товара.
**Ожидаемый результат:** счётчик корзины показывает "3", все три товара присутствуют в корзине.

---

## 3. Страница товара (Product details)

### TC-16. Проверка данных на странице товара

**Шаги:** открыть страницу конкретного товара.
**Ожидаемый результат:** отображаются название, описание, цена и изображение, совпадающие с данными в каталоге.

### TC-17. Добавление/удаление товара со страницы товара

**Шаги:** на странице товара нажать "Add to cart", затем "Remove".
**Ожидаемый результат:** состояние кнопки и счётчик корзины меняются корректно, как и в каталоге.

### TC-18. Возврат в каталог со страницы товара

**Шаги:** нажать кнопку "Back to products".
**Ожидаемый результат:** пользователь возвращается в каталог, ранее выбранная сортировка сохраняется (если это ожидаемое поведение).

---

## 4. Корзина (Cart)

### TC-19. Переход в корзину

**Шаги:** кликнуть на иконку корзины.
**Ожидаемый результат:** открывается страница корзины со списком добавленных товаров.

### TC-20. Корректность состава корзины

**Шаги:** добавить 2 товара в каталоге, открыть корзину.
**Ожидаемый результат:** в корзине отображаются именно эти 2 товара с правильными названиями, ценами и количеством.

### TC-21. Удаление товара из корзины

**Шаги:** в корзине нажать "Remove" у одного из товаров.
**Ожидаемый результат:** товар исчезает из списка, счётчик корзины уменьшается.

### TC-22. Пустая корзина

**Шаги:** удалить все товары из корзины (или зайти в корзину без добавленных товаров).
**Ожидаемый результат:** отображается пустой список товаров, кнопка "Checkout" при этом либо неактивна, либо ведёт к ошибке/пустому заказу (зафиксировать фактическое поведение).

### TC-23. Продолжить покупки из корзины

**Шаги:** в корзине нажать "Continue Shopping".
**Ожидаемый результат:** пользователь возвращается в каталог товаров.

### TC-24. Переход к оформлению заказа

**Шаги:** в корзине с товарами нажать "Checkout".
**Ожидаемый результат:** открывается форма оформления заказа (ввод имени, фамилии, индекса).

---

## 5. Оформление заказа (Checkout)

### TC-25. Успешное заполнение формы checkout с валидными данными

**Шаги:** заполнить First Name, Last Name, Zip/Postal Code корректными значениями, нажать "Continue".
**Ожидаемый результат:** переход на страницу с итоговой информацией о заказе (Overview).

### TC-26. Валидация обязательных полей checkout

**Шаги:** оставить одно из полей (например, First Name) пустым, нажать "Continue".
**Ожидаемый результат:** отображается сообщение об ошибке с указанием, какое поле обязательно.

### TC-27. Проверка итоговой суммы заказа (Overview)

**Шаги:** дойти до страницы Overview после добавления нескольких товаров.
**Ожидаемый результат:** отображается корректный список товаров, Item total, Tax и Total, суммы посчитаны верно (Item total + Tax = Total).

### TC-28. Отмена оформления заказа

**Шаги:** на любом шаге checkout нажать "Cancel".
**Ожидаемый результат:** пользователь возвращается в каталог или в корзину (в зависимости от шага), состояние корзины сохраняется.

### TC-29. Завершение заказа (Finish)

**Шаги:** на странице Overview нажать "Finish".
**Ожидаемый результат:** отображается страница подтверждения заказа ("Thank you for your order" / аналог), корзина очищается.

### TC-30. Возврат в каталог после завершения заказа

**Шаги:** на странице подтверждения заказа нажать "Back Home".
**Ожидаемый результат:** пользователь перенаправлен в каталог товаров, корзина пуста (счётчик не отображается или равен 0).

---

## 6. Меню и логаут

### TC-31. Открытие бокового меню

**Шаги:** нажать на иконку гамбургер-меню.
**Ожидаемый результат:** открывается боковое меню с пунктами (All Items, About, Logout, Reset App State и т.п.).

### TC-32. Успешный логаут

**Шаги:** открыть меню, нажать "Logout".
**Ожидаемый результат:** пользователь разлогинен и перенаправлен на страницу логина.

### TC-33. Reset App State

**Шаги:** добавить товары в корзину, открыть меню, нажать "Reset App State".
**Ожидаемый результат:** корзина очищается, состояние кнопок "Add to cart"/"Remove" сбрасывается на исходное.

### TC-34. Попытка прямого доступа к защищённой странице без авторизации

**Шаги:** будучи неавторизованным, попытаться открыть URL страницы каталога/корзины напрямую.
**Ожидаемый результат:** пользователь перенаправлен на страницу логина.

### TC-35. Проверка поведения после логаута при попытке вернуться назад (browser back)

**Шаги:** выполнить логаут, затем нажать кнопку "Назад" в браузере.
**Ожидаемый результат:** приложение не показывает защищённый контент повторно, либо перенаправляет на логин.

---

## Рекомендации по автоматизации

- Кейсы TC-01–TC-08 удобно объединить в один параметризованный тест (data-driven) с разными наборами логин/пароль.
- Для TC-10–TC-11 (сортировка) стоит вынести проверку сортировки списка в отдельный переиспользуемый метод/утилиту.
- Кейсы с корзиной (TC-19–TC-24) и checkout (TC-25–TC-30) образуют сквозной сценарий (end-to-end) — имеет смысл написать и как отдельные тесты, и как единый smoke-сценарий "полный путь покупки".
- Для проверок сумм (TC-27) заранее продумать тестовые данные с известными ценами, чтобы упростить assert.
